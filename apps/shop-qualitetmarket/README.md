# Shop Qualitet Builder

This is the standalone Shop Builder application in `apps/shop-qualitetmarket`.
It does not configure DNS, Cloudflare, Render, or routing in other apps.

## Run locally

Install dependencies and start the application from this directory:

```powershell
npm ci
npm run dev
```

The application requires a MongoDB database configured through `MONGODB_URI`.
`MONGODB_DATABASE` may optionally select a database. The MongoDB credentials
should be scoped to the required Shop collections.

## Shop owner authentication

Configure these values in the Shop deployment environment; do not commit them:

- `SHOP_OWNER_EMAIL`: the Shop owner sign-in address.
- `SHOP_OWNER_PASSWORD_HASH`: a `scrypt` password hash generated by
  `npm run auth:hash-password`. The script reads the password without echoing
  it; it does not accept a password as a command-line argument.
- `SHOP_SESSION_SECRET`: a randomly generated secret of at least 32 bytes.

For example, generate a session secret with:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

The Shop session uses an HTTP-only, host-only `shop_session` cookie. It does
not read or modify the marketplace's `henryk_session` cookie.

## Persistent data

- Stores are read from and written to MongoDB's `stores` collection.
- Products are created, listed, edited, and deleted in MongoDB's existing
  `products` collection, scoped by the selected store ID.
- Categories are created, listed, edited, and deleted in the Shop-specific
  MongoDB `shop_categories` collection and scoped to a store and its Shop
  owner. The marketplace's `categories` collection is not modified.
- Dashboard counts are read from the `products`, `shop_categories`,
  `customers`, and `orders` collections using the selected store ID.
- Shop settings include the store description, logo and favicon URLs, contact
  details, and social links. Design settings include a theme, colors, logo URL,
  and up to ten banner image URLs. URLs must use HTTP or HTTPS.
- Shop authentication sessions and failed-login counters are stored in the
  `shop_sessions` and `shop_login_attempts` collections.

All management pages require an authenticated Shop owner. Requests that modify
store or category data also require a same-origin request. MongoDB connection,
validation, and persistence failures return an error rather than sample data.
